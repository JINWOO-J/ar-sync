# Requirements: Bidirectional Sync

## Overview

ar-sync CLI의 양방향 동기화 기능 요구사항 문서입니다. Project ↔ Store ↔ Remote 간의 완전한 동기화를 구현합니다.

## User Stories

### 1. 기본 동기화 흐름
- 1.1: 사용자는 `ars sync` 명령으로 양방향 동기화를 수행할 수 있어야 함
- 1.2: Remote → Store → Project 순서로 변경사항이 전파되어야 함
- 1.3: 충돌이 없으면 자동으로 동기화되어야 함
- 1.4: 네트워크 에러 시 적절한 에러 메시지를 표시해야 함
- 1.5: 파일 권한 에러 시 복구 단계를 제공해야 함

### 2. 파일 비교 및 변경 감지
- 2.1: 추가된 파일을 감지할 수 있어야 함
- 2.2: 수정된 파일을 감지할 수 있어야 함
- 2.3: 삭제된 파일을 감지할 수 있어야 함
- 2.4: 콘텐츠 기반 비교를 수행해야 함 (타임스탬프 무시)
- 2.5: 심볼릭 링크는 자동으로 스킵해야 함
- 2.6: 변경사항이 없으면 "Already in sync" 메시지를 표시해야 함

### 3. Diff 출력
- 3.1: Git diff 형식으로 변경사항을 표시할 수 있어야 함
- 3.2: --diff 옵션으로 diff만 표시할 수 있어야 함
- 3.3: 바이너리 파일은 "Binary files differ" 메시지를 표시해야 함
- 3.4: 색상 코딩으로 가독성을 높여야 함
- 3.5: 파일 경로와 변경 타입을 명확히 표시해야 함

### 4. 충돌 감지
- 4.1: 로컬과 원격이 모두 수정된 파일을 감지해야 함
- 4.2: 충돌 파일 목록을 사용자에게 표시해야 함
- 4.3: 각 충돌에 대한 해결 옵션을 제공해야 함
- 4.4: 충돌 해결 전까지 동기화를 중단해야 함

### 5. 충돌 해결
- 5.1: 대화형 모드에서 사용자가 해결 방법을 선택할 수 있어야 함
- 5.2: 로컬 버전 사용 옵션을 제공해야 함
- 5.3: 원격 버전 사용 옵션을 제공해야 함
- 5.4: 3-way 병합 옵션을 제공해야 함
- 5.5: 건너뛰기 옵션을 제공해야 함
- 5.6: 병합 시 충돌 마커를 감지해야 함
- 5.7: 바이너리 파일은 병합을 거부해야 함

### 6. 자동 해결 전략
- 6.1: --local 옵션으로 항상 로컬 우선 전략을 사용할 수 있어야 함
- 6.2: --remote 옵션으로 항상 원격 우선 전략을 사용할 수 있어야 함
- 6.3: 자동 전략 사용 시 대화형 프롬프트를 표시하지 않아야 함
- 6.4: 자동 해결된 파일 목록을 표시해야 함

### 7. Dry-run 모드
- 7.1: --dry-run 옵션으로 미리보기 모드를 제공해야 함
- 7.2: Dry-run 모드에서는 실제 파일을 수정하지 않아야 함
- 7.3: 수행될 작업 목록을 표시해야 함
- 7.4: 충돌 감지는 수행해야 함
- 7.5: "Dry-run mode" 표시를 명확히 해야 함

### 8. 결과 보고
- 8.1: 동기화 완료 후 결과 요약을 표시해야 함
- 8.2: Pull된 파일 수를 표시해야 함
- 8.3: Push된 파일 수를 표시해야 함
- 8.4: 충돌 수를 표시해야 함
- 8.5: 스킵된 파일 수를 표시해야 함

### 9. 방향 제어
- 9.1: --pull-only 옵션으로 Pull만 수행할 수 있어야 함
- 9.2: --push-only 옵션으로 Push만 수행할 수 있어야 함
- 9.3: 방향 제어 시 해당 단계만 실행해야 함
- 9.4: 방향 제어 옵션은 상호 배타적이어야 함

### 10. 파일 메타데이터 보존
- 10.1: 파일 권한을 보존해야 함
- 10.2: 타임스탬프를 보존해야 함
- 10.3: 디렉토리 권한을 보존해야 함

### 11. 에러 처리
- 11.1: 모든 에러에 대해 명확한 메시지를 제공해야 함
- 11.2: 에러 발생 시 롤백을 지원해야 함
- 11.3: 복구 단계를 제공해야 함
- 11.4: 파일 경로를 포함한 상세 정보를 제공해야 함
